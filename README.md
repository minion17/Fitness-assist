# Setly

Telegram-бот с Mini App для дневника питания, тренировок и отслеживания прогресса.

**Этап 1 — технический фундамент:** бот с `/start` и кнопкой запуска Mini App, интерфейс из 4 разделов на демо-данных, FastAPI + PostgreSQL, проверка подписи Telegram initData, `/health`.

## Стек

- Backend: Python 3.11+, FastAPI, aiogram 3, SQLAlchemy 2 (async) + PostgreSQL
- Frontend: React, TypeScript, Vite

## Структура

```
backend/
  api/       FastAPI: /health, /api/auth; раздаёт собранный Mini App
  bot/       aiogram-бот: /start, кнопка Mini App, обработка ошибок
  core/      настройки (.env), проверка Telegram initData
  database/  подключение к PostgreSQL, модель User
frontend/    Mini App (React + TS + Vite)
content/     products / exercises / programs — данные со второго компьютера
docs/
tests/       тесты backend (pytest)
```

## Запуск локально

Нужны: Python 3.11+, Node.js 20+, Docker (или свой PostgreSQL).

```bash
cp .env.example .env            # впишите BOT_TOKEN и WEBAPP_URL

docker compose up -d db         # PostgreSQL

python -m venv .venv
source .venv/bin/activate       # Windows: .venv\Scripts\activate
pip install -r backend/requirements.txt

cd frontend && npm install && npm run build && cd ..

uvicorn backend.api.main:app --port 8000     # API + Mini App на http://localhost:8000
python -m backend.bot.main                   # бот (во втором терминале)
```

Telegram открывает Mini App только по HTTPS. Самый простой вариант — туннель:

```bash
cloudflared tunnel --url http://localhost:8000
```

Полученный `https://….trycloudflare.com` впишите в `WEBAPP_URL` и перезапустите бота. Адрес меняется при каждом запуске туннеля — для постоянного адреса нужен свой домен или хостинг.

Разработка интерфейса с горячей перезагрузкой: `cd frontend && npm run dev` (порт 5173, `/api` проксируется на 8000).

## Запуск на Windows (PowerShell, без Docker)

Разовая подготовка уже описана выше; PostgreSQL — из zip-архива в `C:\pgsql`, база `fitness`, вход без пароля (`DATABASE_URL=postgresql+asyncpg://postgres@localhost:5432/fitness`).

**Запуск — двойной щелчок по `start.bat`** в папке проекта. Он сам поднимает базу, сервер, туннель (с автопереподключением; новый адрес пишется в `.env`) и бота — каждый в своём окне (`FA сервер`, `FA туннель`, `FA бот`). Уже запущенное повторно не стартует. Через ~10 секунд отправьте боту `/start`.

**Обновление — двойной щелчок по `update.bat`**: `git pull`, зависимости Python и npm, сборка интерфейса. После обновления закройте окна FA и снова запустите `start.bat`.

Остановить — закрыть окна FA. Удобно вынести ярлык `start.bat` на рабочий стол (ПКМ → Отправить → Рабочий стол).

Cloudflare-туннель в этой сети не работает (заблокирован порт 7844), поэтому localhost.run. Запасной вариант: `ssh -p 443 -R0:localhost:8000 a.pinggy.io`.

## API

| Метод | Путь | Описание |
|---|---|---|
| GET | `/health` | Статус сервиса и БД |
| POST | `/api/auth` | Заголовок `Authorization: tma <initData>`. Проверяет подпись, создаёт/обновляет пользователя, возвращает уровень и анкету |
| GET | `/api/profile` | Анкета пользователя и дневная норма КБЖУ (`null`, если не заполнена) |
| PUT | `/api/profile` | Сохранить анкету: `sex`, `birth_year`, `height_cm`, `weight_kg`, `activity`, `goal` + необязательные `experience`, `equipment[]`, `sessions_per_week`, `session_minutes`, `allergies[]`, `meals_per_day`, `sleep_hours`, `stress`, `injury`. Неверные значения → 422 |

## Анкета (регистрация)

Пошаговая анкета из 6 экранов по образцу Logos engine коллеги: о себе → цель → опыт и активность → тренировки (оборудование, дни, длительность) → питание (аллергии, приёмы пищи) → восстановление (сон, стресс, травмы). Показывается при первом входе, редактируется из профиля. Ответы — в таблице `profiles` (новые поля необязательны, старые профили остаются валидными).

- **Норма КБЖУ** — один расчёт на сервере, `backend/core/nutrition.py`: Миффлин — Сан Жеор × активность × цель. 5 целей и их поправки из Logos: снижение веса −20 %, снижение % жира −15 %, поддержание, набор мышц +15 %, набор массы +20 %. Белок 1,6–2 г/кг, жиры 0,9 г/кг, остальное — углеводы; нижняя граница 1500 ккал (м) / 1200 ккал (ж). Старые цели `lose/maintain/gain` переводятся автоматически при запуске сервера.
- **Подбор программы** — `backend/core/programs.py`: оценка 0–100 по оборудованию (40), уровню подготовки (30) и числу дней (30). Лучшая программа приходит в `/api/auth` как `recommended_program` и показывается первой с пометкой «Подходит вам» и причинами; выбор остаётся за пользователем.
- Сон, стресс, травмы и аллергии передаются в AI-итог.

## Данные и журналы

Справочники лежат в `content/` в JSON и загружаются в базу командой `python -m backend.seed.import_data` (`start.bat` делает это сам при каждом запуске). Повторный импорт безопасен: существующие записи (по названию) пропускаются.

| Файл | Поля |
|---|---|
| `content/products/products.json` (~340 продуктов: базовые позиции коллеги + обычные продукты с КБЖУ из USDA SR28 — лабораторные данные Минсельхоза США, названия переведены) | `name`, `brand`, `barcode`, `category`, `kcal`, `protein_g`, `fat_g`, `carbs_g` (на 100 г) |
| `content/exercises/exercises.json` | `name`, `muscle_groups[]`, `equipment[]`, `difficulty`, `description`, `is_bodyweight` |
| `content/programs/programs.json` | `name`, `goal`, `level`, `days_per_week`, `description`, `days[]` → `day_name`, `day_order`, `exercises[]` → `name` (из exercises.json), `sets`, `reps`, `rest_seconds`, `notes` |

API:

| Метод | Путь | Описание |
|---|---|---|
| GET | `/api/products/search?q=` | Поиск продуктов (от 2 символов, без учёта регистра) |
| GET | `/api/exercises`, `/api/programs` | Упражнения; программы с днями и упражнениями |
| POST/GET | `/api/food-logs` | Добавить запись `{product_id, amount_g, meal_type}` / записи и итоги КБЖУ за день (`?day=YYYY-MM-DD`) |
| POST | `/api/workout-logs` → `/{id}/sets` → `/{id}/complete` | Начать тренировку, записать подходы, завершить |
| GET | `/api/workout-logs` | История тренировок |
| DELETE | `/api/food-logs/{id}` | Удалить запись из дневника питания |
| PUT/GET | `/api/measurements` | Замер за день `{measured_on?, weight_kg, waist_cm, chest_cm, hips_cm, body_fat_pct}` (повторное сохранение за тот же день заменяет запись; новый вес обновляет анкету и норму) / история, новые сверху |
| DELETE | `/api/measurements/{id}` | Удалить замер |
| GET | `/api/products/recent` | Недавние продукты пользователя с последней порцией |
| GET, PUT/DELETE | `/api/favorites`, `/api/favorites/{product_id}` | Избранные продукты |
| GET | `/api/products/barcode/{code}` | Товар по штрихкоду: сначала наш каталог, иначе Open Food Facts (найденный товар сохраняется в общий каталог; 404 — не найден, 503 — OFF недоступен) |
| POST | `/api/products` | Свой продукт `{name, kcal, protein_g, fat_g, carbs_g}` на 100 г — виден только автору |
| POST | `/api/food-logs/copy` | Повторить приём пищи `{from_day, meal_type}` из последних 30 дней в сегодня |
| GET/POST | `/api/water` | Вода за сегодня `{ml, goal_ml}` / изменить `{delta_ml}` (±1000). Норма — 33 мл на кг веса, 1,5–4 л |
| GET | `/api/week` | Последние 7 дней (ккал, вода, тренировки) и серия активных дней подряд |

XP: приём пищи — 10 XP один раз на тип приёма в день; тренировка — 50 XP, только если есть хотя бы один подход; замер — 15 XP раз в день; норма воды — 10 XP раз в день. Удаление записи XP не отнимает.

## AI (Claude API)

Включается ключом `ANTHROPIC_API_KEY` в `.env` (получить: https://console.anthropic.com → API Keys). Без ключа приложение работает, AI-кнопки скрыты.
Модель — `AI_MODEL` (по умолчанию `claude-haiku-5-5`: быстрая и дешёвая). Лимит — `AI_DAILY_LIMIT` запросов на пользователя в день.

- **Еда текстом / по фото** (`POST /api/ai/meal/text`, `/api/ai/meal/photo`) — AI разбирает описание или фото на продукты и граммы и возвращает **черновик**; в дневник ничего не пишется. Каталог продуктов передаётся модели: найденные продукты берут КБЖУ из базы, остальные — оценку AI (с ограничением абсурдных значений). Пользователь правит граммы и подтверждает (`POST /api/ai/meal/confirm`). Неизвестные блюда сохраняются как личные продукты пользователя (`products.owner_user_id`) — видны только ему, общий каталог не засоряют.
- **Итог дня / недели** (`GET /api/ai/summary?period=day|week`) — короткий разбор по реальным данным (норма, питание по дням, тренировки, вес) и совет. Кешируется на день; `refresh=true` — пересчитать.
- **Этикетка** (`POST /api/ai/label`) — фото таблицы «Пищевая ценность» → КБЖУ на 100 г для формы «Свой продукт» (когда товара нет ни в каталоге, ни в Open Food Facts). Только напечатанные цифры, значения ограничиваются; пользователь проверяет и сохраняет.
- **Меню ресторана** (`POST /api/ai/menu`) — фото меню или карточки блюда в приложении доставки → список блюд с напечатанными КБЖУ (на 100 г) и весом порции; пользователь отмечает нужные, указывает заведение и сохраняет как свои продукты (`brand` = заведение).
- `GET /api/ai/status` — включён ли AI и сколько запросов осталось.

Код: `backend/core/ai.py` (обёртка над API), `backend/api/ai.py` (промпты, черновики, лимит, кеш). В тестах модель подменяется — тесты не тратят деньги.

Перекусы: кнопка «+ Перекус» создаёт отдельный перекус с текущим временем (`food_logs.snack_slot`, «11:30»); перекусов за день сколько угодно, каждый — своя карточка со своей суммой, карточки идут по времени между завтраком, обедом и ужином.

Штрихкод: в окне «Добавить продукт» → «▥ Сканировать штрихкод» открывается живая камера прямо в приложении (кадр распознаётся несколько раз в секунду); если камера недоступна — «Фото из галереи» или «Ввести цифры». Код читается — обычный штрихкод EAN/UPC или квадратный DataMatrix «Честного знака» (из него берётся код товара). Распознаёт встроенный детектор телефона, иначе zxing-cpp (WebAssembly ~420 КБ в gzip, отдаётся нашим сервером и грузится только при первом сканировании). Не распозналось — можно ввести цифры. Товара нет в Open Food Facts — форма «Свой продукт», и этот штрихкод дальше находит его (только у этого пользователя, таблица `user_barcodes`). Каталог растёт только за счёт отсканированных товаров, а не выгрузки всей базы.

## Общая база из пользовательских продуктов

Свои продукты (`POST /api/products`) видны только автору. Если **3 разных пользователя** ввели одно и то же — тот же штрихкод или то же название + бренд/заведение — с совпадающими цифрами (ккал ±5%, БЖУ ±10% или ±1 г), в общий каталог добавляется копия со средними значениями (категория «Проверено пользователями»), и дальше её находят все — поиском и сканером. Продукты без бренда и штрихкода («сырник домашний») не обобщаются. Порог — `CONFIRMATIONS` в `backend/api/quick_food.py`.

Порции: у продукта может быть `portion_g` / `portion_name` («пицца», 610 г) — в окне добавления появляются кнопки «½ · 1 пицца · ×2».

## Прогресс и достижения

Вкладка «Прогресс» (`GET /api/stats?days=7|30|90`): итоги периода, графики калорий (с линией нормы), веса, воды, средние БЖУ и рабочие веса по упражнениям (лучший подход за день); там же замеры тела.

Достижения (`GET /api/achievements`, список — `ACHIEVEMENTS` в `backend/api/stats.py`) считаются по данным пользователя; открытие сохраняется один раз (`user_achievements`), даёт +25 XP и показывает экран награды (`POST /api/achievements/seen` — показан). Заморозка серии: за каждые 7 дней подряд +1 (максимум 2, +20 XP); пропущенный день перед сегодняшним закрывается заморозкой автоматически (`frozen_days`).

## Профиль бота

Аватар (`backend/bot/assets/avatar.jpg`, исходники — `avatar*.svg`), описание и короткое описание задаются в `backend/bot/profile.py` и применяются ботом при запуске — только если что-то изменилось (отпечаток хранится в `.bot_profile`). Поменять: отредактировать тексты или картинку и перезапустить бота.

## Картинки в сообщениях бота

`backend/bot/cards.py` рисует карточки (Pillow, шрифты Manrope/Unbounded под OFL в `backend/bot/assets/fonts`) в стиле приложения и в теме пользователя: обложка на /start, напоминание о еде — с кольцом калорий и БЖУ за сегодня, о воде — с выпитыми стаканами, о серии — с числом дней и неделей. Рисуются в отдельном потоке перед отправкой (~0,3 с); если картинка не получилась, уходит обычный текст.

## Напоминания в боте

Бот раз в минуту проверяет, кому пора напомнить (`backend/bot/reminders.py`, запускается вместе с ботом): не записанный завтрак/обед/ужин в выбранное время, вода в 12/16/19 ч если выпито меньше 35/60/85% нормы, серия дней вечером если сегодня ничего не записано. По воскресеньям (время настраивается) — итоги недели: карточка с калориями по дням и линией нормы, дни в норме, вода, тренировки, вес и совет AI (если ключ задан; в дневной лимит пользователя не идёт). Каждое напоминание записывается в `reminders_sent` до отправки — повторов не будет даже после перезапуска; пропущенное из-за перезапуска отправляется только в течение 45 минут. Настройки — Профиль → «Напоминания в боте» (`GET/PUT /api/reminders`). Получают только заполнившие анкету. Время — по часам сервера.

Вода: кнопки +150/+250/+330/+500, «Своё» (10–1000 мл) и «↶» — отменяет последнее добавление.

## Оформление

Главная: большое кольцо калорий, БЖУ, быстрые кнопки «Сфоткать еду» / «Вручную», тренировка дня, трекер воды, неделя из мини-колец и серия дней (🔥). При новом уровне — полноэкранный экран награды.

Темы (`frontend/src/theme.ts`, переменные в `index.css` по `data-theme`): «Как в Telegram» (светлая/тёмная по теме Telegram), «Тёмная» (+ 4 акцента), «Светлая», «Салатовая». Выбор — в Профиле → «Оформление», хранится на устройстве.

## Геймификация

- `users.xp`, `users.level` — общий опыт и уровень.
- `backend/core/gamification.py` — правила наград (`RULES`: событие → XP) и расчёт уровня: до 2-го уровня 100 XP, каждый следующий шаг +50.
- `backend/database/rewards.py` — `award_xp(session, user_id, event_type, event_key)`. Таблица `xp_events` с уникальным ключом `(user_id, event_key)` не даёт начислить XP дважды за одно событие, даже при повторах и параллельных запросах. `event_key` — идентификатор источника, например `meal:123`.
- `/api/auth` возвращает `progress`, профиль показывает уровень и прогресс-бар.

Начисляется за дневник питания и завершённые тренировки (см. выше).

## Для владельца: ошибки, копии, рассылка, статистика

Всё это работает, когда в `.env` указан ваш Telegram ID: `ADMIN_IDS=123456789` (бот подскажет ID в ответ на `/stats`).

- **Ошибки.** Сбой сервера, бота или приложения у пользователя приходит вам сообщением от бота. Одинаковая ошибка — не чаще раза в 30 минут.
- **Резервные копии.** Раз в сутки сервер сохраняет копию базы в папку `backups/` (хранятся последние 14). Если `pg_dump` не нашёлся сам, укажите путь: `PG_DUMP=C:\pgsql\bin\pg_dump.exe`. Восстановить базу из копии:
  `pg_restore --clean --if-exists -h localhost -U fitness -d fitness backups\setly-ГГГГ-ММ-ДД-ЧЧММ.dump`
  Копии лежат на том же компьютере, что и база: от поломки диска они не спасут — время от времени переносите свежую копию в облако.
- **Рассылка.** `/broadcast текст` — бот покажет, как будет выглядеть сообщение и скольким людям уйдёт, и отправит только после кнопки «Отправить».
- **Статистика.** `/stats` — пользователи, возвраты, чем пользуются.
